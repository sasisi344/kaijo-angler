# ランキング記事ライティングルール

`column/ranking/` 配下の地域別海上釣り堀ランキング記事の作成規則。
確定テンプレートは `src/content/blog/column/ranking/kansai/index.mdx` を参照。

---

## 1. ファイル配置

```
src/content/blog/column/ranking/{region-slug}/index.mdx
```

`{region-slug}` の命名規則：

| 対象エリア | slug |
| :--- | :--- |
| 大阪・兵庫 | `kansai` |
| 三重・和歌山 | `mie-wakayama` |
| 中国・四国 | `chugoku-shikoku` |
| 九州・沖縄 | `kyushu-okinawa` |
| 日本海側・北陸 | `nihonkai-hokuriku` |
| 関東・静岡・愛知 | `kanto-tokai` |
| 北日本・東北 | `tohoku-hokkaido` |

## 2. フロントマター

```yaml
---
title: "{エリア名}の海上釣り堀おすすめランキング｜{都道府県}の施設を比較"
publishDate: YYYY-MM-DD
category: "釣り場ランキング"
draft: false
tags:
  - "ランキング"
  - "{エリア名}"
  - "{都道府県名1}"
  - "{都道府県名2}"
  - "海上釣り堀"
description: "{都道府県}の海上釣り堀を料金・アクセス・魚種で比較。〜目的別おすすめTOP3を紹介します。"
---
```

- `image` フィールドは cover.jpg が存在する場合のみ追加する（記事にプロンプトを書いた段階で生成してよい。2026-11-06 ユーザー決定）
- タイトル・description に年の「最新」表記と「徹底比較」は付けない（`CLAUDE.md`、2026-11-15）
- `category: "釣り場ランキング"` に固定（`travel`・`trivia` と区別するため）
- タイトルの施設数 N は<strong>稼働中の海上釣り堀のみ</strong>をカウントする（休止中・閉園は含まない）

---

## 3. 対象施設の選定ルール

**海上釣り堀のみをランキング対象とする。**

施設の frontmatter `tags` に `海上釣り堀` が含まれているものを対象とする。以下は除外する：

| タグ | 除外理由 |
| :--- | :--- |
| `海釣り施設` | 護岸・公営桟橋型（放流管理なし） |
| `海釣り公園` | 護岸・桟橋型の海釣り公園 |
| `status: closed` または `status: suspended` | 閉園・休止中 |

- 休止中・閉園施設は一覧テーブルに残すが、施設名の後に `※2026年〇月より無期限休止中` と明記し、アクセス欄は `—` にする
- タイトルの施設数・TOP3・目的別まとめには含めない

---

## 4. H2 セクション構成（固定）

以下の順序を守る。

```
## おすすめTOP3
## {都道府県A}の海上釣り堀（N施設）    ← 府県ごとに繰り返す
## {都道府県B}の海上釣り堀（N施設）
## {エリア名}の海上釣り堀を分析する
## 目的別おすすめまとめ
## これだけは持っていきたい！おすすめアイテム
```

## 5. 各セクションの書き方

### リード文（2026-11-15 追加。`kaijo-writing-rule.md` §4.1-3）

- ランキングは流入がいちばん多いのに、滞在は1PVあたり36秒、最後まで読む人は8%（10/1〜11/14）。**答えを冒頭に置く**
- リード文の中に「迷ったらここ」を読者のタイプ別に2〜3行で書く（はじめて・家族・大物狙いなど）。1行に施設名（内部リンク）・料金・決め手を1つ
- 施設数や地理の説明は、その後に回す

### おすすめTOP3

- 1〜3位それぞれに H3 見出し（`### 1位　[施設名](パス)（都道府県・地区名）`）
- 各位に2〜3文の説明 ＋ `- <strong>料金</strong>：` `- <strong>アクセス</strong>：` の箇条書き
- **料金は施設記事の数値を書く**（数値の正本は施設記事）。「要問合せ」と書けるのは、施設記事にも料金がないときだけ。その場合は「公式で案内なし（予約時に確認）」と書く
- 説明は、その施設での一日が浮かぶ事実から入る（何が釣れ、釣ったあと何ができるか）。「世界最大級」「迷わず第一候補」のような、確かめていない大きさ・断定は書かない
- 選定軸：本格度・旅行適性・初心者向けの3軸で異なるタイプの施設を選ぶ
- 休止中・閉園施設はTOP3に含めない

### {都道府県}の海上釣り堀

- エリアの地理的特徴を1〜2文で書いてからテーブルへ
- テーブルの列：`施設名（内部リンク）` | `特徴` | `アクセス`
- テーブルの後に「エリアの選び方」を箇条書き（目的 → 施設名の形式）

```markdown
| 施設名 | 特徴 | アクセス |
| :--- | :--- | :--- |
| [施設名](/fishing-facility/...) | 特徴を端的に | 最寄り駅・港 |
```

### {エリア名}の海上釣り堀を分析する

プレゼン資料的な俯瞰コンテンツ。以下の4ブロックで構成する：

1. **施設数と分布：{比較対象エリア}との比較**
   - 施設数・国際空港アクセス・放流魚の最高クラス・施設タイプの多様性・旅行適性を5行の比較表にまとめる

2. **地理的優位性：{海域名}が生む「釣り堀の適地」**
   - 海域の地形的特性（内湾・波・潮流）が施設集積を生む理由を2〜3段落で説明

3. **アクセス構造：{主要起点}を起点にした旅行動線**
   - 出発地・手段・所要時間の3列テーブルで主要ルートを示す

4. **施設タイプ別の特性まとめ**
   - タイプ名・該当施設・向いている人の3列テーブルで3〜4タイプに分類する

### 目的別おすすめまとめ

2列テーブル（目的 | おすすめ施設）。6〜8行を目安に、初心者・家族・ガチ勢・電車族・天候別など多様なニーズをカバーする。

**リード文の「迷ったらここ」と同じ目的の行は、同じ施設にする**（2026-11-19 ユーザー決定）。「迷ったらここ」が記事の中の正本。別の観点で勧めたい施設は、「ボウズ保証で選ぶなら」のように目的の名前を変えた行にする。

### 行き先が決まったら、〇〇（カードの節。2026-11-19 位置を確定）

**位置（2026-11-19 ユーザー決定。WR-2）**: 最後まで読む人が8%なので、カードは読み終えた後に置かない。

1. **1枚目は「おすすめTOP3」の直後**に H2 の節を1つ作って置く（見本: kansai「行き先が決まったら、前の晩にどこで寝るか」）。TOP3 と「迷ったらここ」に出た施設の事実（受付時刻・料金）で場面を書く
2. **2枚目は、場面がある記事だけ**、結び（「行くと決めたら」）の前に置く（見本: kansai「関西への旅行を計画しているなら」）。場面がなければ1枚で終える
3. 「分析」の先頭には置かない。TackleCard を複数並べる「おすすめアイテム」節は作らない

場面は読者の選択を決めつけない（「行き先はサザンに決まった」ではなく「サザンに決めた人は」。`kaijo-writing-rule.md` §4.1-1）。

書き方は `card-rules.md` の5段（場面→原因→基準→カード→正直さ）と §3-2 に従う。物販は場面の数だけ（1〜2枚）。見本は `column/ranking/kansai`。

---

## 6. 全体の記述ルール

- 強調は `<strong>テキスト</strong>` を使用（`**bold**` は使わない）
- 施設への内部リンクは `/fishing-facility/{region}/{prefecture}/{slug}` の絶対パスで書く
- 「あわせて読みたい」セクションはリンク先の記事が存在する場合のみ追加する
- `import TackleCard from "~/components/common/TackleCard.astro";` を frontmatter 直後に記述する

---

## 7. 旧WordPressまとめ記事とのリダイレクト対応

旧URLのリダイレクトは `src/config/blog-legacy-redirects.ts` にエントリを追加する（`astro.config.ts` の `redirects` が読む）。
旧WordPressの記事とURLの一覧は `.data-set/wordpress-log/WordPress.2026-03-20.xml` を参照。
