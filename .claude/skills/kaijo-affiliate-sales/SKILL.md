# kaijo-angler アフィリエイト販売設計（売り方のルール）

挿し方（import・id・rel）は `kaijo-ui-components`。このスキルは **なぜ・誰に・どこで・何と書いて勧めるか** を決める。
背景と分析は `.workspace/.task/travel-cta-sales-design.md`、ASP の割り当ては `src/data/travel-asp-profile.json` の `placementPolicy`。

## 3原則

1. **必然性**: CTA の直前に「施設の事実 → この商品が要る理由」をつなぐ一文を書く。理由のない CTA は置かない
2. **1面1提案**: 1つの面に出す商材は1つ。じゃらん＋楽天のように同じ種類を2枚並べて選択を読者に投げない
3. **熱い場所**: 関心が生まれた段落の直後に置く。記事末だけに置かない

## 手順

### Step 1. 読者タイプを判定する（データで）

次の3つを見る。推測で決めない。

| 見るもの | 場所 |
|---|---|
| 施設の事実 | frontmatter（`prefecture`・`business_hours`・`parking`・`reservation`・`needs_ferry`）、記事末の `> [!forAI]`（運営者の一次メモ。最優先） |
| 読者の出発地 | 最新週の GA4（`.workspace/.task/access-data/weekly-report/<年>/wNN/*-ga4-*.csv`）で対象ページの `session_start` を市区町村別に集計 |
| 検索意図 | 同じ週の GSC `クエリ.csv`（施設名＋「料金」「駐車場」「アクセス」「ホテル」など） |

```bash
# 例: 対象ページのセッションを都市別に集計
grep "<slug>" wNN-ga4-kaijo.csv | grep ",session_start," | awk -F, '{c[$5]+=$6} END{for(k in c) print c[k], k}' | sort -rn
```

注意: GA4 の都市はモバイル回線だと東京（Shinjuku City 等）に寄ることがある。週20セッション未満なら傾向として扱い、断定しない。

| 読者タイプ | 判定の目安 | 主役の商材 | 補助 |
|---|---|---|---|
| **A 飛行機で来る**（沖縄・九州・北海道・離島） | 本文に空港への言及、空港から車移動 | 空港発のレンタカー（GoThere の rentacar） | 前泊の宿／自宅⇔空港の送迎（`travel/nearme-airport-transfer`） |
| **B 早朝受付・遠方** | 受付が早い＋主要出発地から遠い | 前泊の宿（本文中は楽天トラベル） | レンタカー |
| **C 離島・フェリー** | `needs_ferry` やアクセス節の渡船・フェリー | 港近くの前泊の宿 | — |
| **D 観光地** | 周辺観光の節がある | 宿（観光と組み合わせる） | アクティビティ（ディープリンク未検証なので保留） |
| **E 都市近郊・日帰り** | 三大都市圏の都市部、読者の大半が同じ府県 | **物販（その釣り場のルールに合う道具）** | 旅行は条件付き（下記） |

**E の旅行 CTA の条件**: 次の両方を満たすときだけ、アクセス節に宿泊を1つ出す（記事末には出さない）。
- 遠方の読者が一定数いる（目安: GA4 で同府県外が2割以上）
- 前泊の必然性を一次情報で書ける（例: 早朝開園で「開園前に並べる近くの人が有利」）

### Step 2. つなぎの一文を書く

型: **〈施設の事実（数値・ルール）〉＋〈それで読者が困ること〉＋〈だからこの商品〉**

| 用途 | 例 |
|---|---|
| 前泊 | 「4〜11月は朝5時に開園し、開園前から場所を選べる近くの人ほど有利です。遠方から朝に間に合わせるなら、前日のうちに大阪に泊まっておくと動きやすくなります」 |
| レンタカー | 「那覇空港から車で30分。バスの乗り継ぎより、空港でレンタカーを借りるのが最短です」 |
| 物販（ルール起点） | 「売店に活き餌はありません。使うなら来る途中で用意を」／「竿出しは1人1本。持ち込みは自由なので、狙いに合わせて持ち替えを」 |
| 物販（魚種起点） | 「タチウオの歯や暴れる青物を素手でつかまずに済みます」 |

- 使ってよい根拠: frontmatter、記事本文、`> [!forAI]`、`.data-set`（魚種は `kaijo-fish-knowledge` 経由）。**所要時間・価格・時刻を推測で書かない**
- 宣伝文句（「日本最大級」「爆釣」）ではなく、読者の困りごとを書く
- 文は `GoThere` の `lead`、`AffiliateCard`／`TackleCard` の `reason` に渡す。JSON の汎用説明文のまま出さない

### Step 3. 置く場所と placement

| 位置 | 形 | placement |
|---|---|---|
| 冒頭の旅行フックの直後（A〜D のみ） | 1行のテキスト＋アクセス節への内部リンク | — |
| ルール・攻略の節（その道具が要る理由が出た直後） | `TackleCard`（reason 付き） | `facility-gear` |
| **アクセス節（主戦場）** | つなぎの一文＋`GoThere` 1つ | `facility-access` |
| 記事末 | 補助の CTA（A〜D のみ。E は置かない） | `facility-footer` |
| 準備の節（道具の運び方など、旅行の段取りが出た直後） | `AffiliateCard`（reason・ctaLabel 付き。空港送迎など） | `facility-prep` |

- 1記事に `GoThere` を2つ置くときは placement を必ず分ける
- ランキング／まとめ記事は `ranking-…`／`matome-…` の既存命名に従う（`kaijo-matome-hub`）

### Step 4. コンポーネントの使い方

```mdx
<GoThere
  facilityId="west-japan/osaka/nanko-fishing-park"
  placement="facility-access"
  heading="遠方から行くなら：ルートと前泊の宿"
  lead="（Step 2 のつなぎの一文）"
  lodging="show"        // auto（都道府県で判定）/ show（近隣でも出す）/ hide
  lodgingAsp="rakuten"  // both / rakuten（本文中）/ jalan（記事末）
  rentacar="hide"       // auto / hide（都市近郊・公共交通が便利な施設）
  maps={false}          // 2つ目の GoThere（記事末の宿泊枠など）でルートボタンを重複させない
/>

<TackleCard id="tackle/aji-strategy-set" placement="facility-gear" reason="（この釣り場でこれが要る理由）" />
<AffiliateCard id="travel/nearme-airport-transfer" isVertical={true} placement="facility-footer"
  reason="（施設の事実 → 送迎が要る理由）" ctaLabel="空港までの送迎料金を見る" />
```

- 既定値（props なし）は従来どおり動く。既存の116記事を一斉に書き換える必要はない
- ASP の選び方: 本文中の宿泊＝楽天トラベル、記事末の宿泊＝じゃらん、レンタカー＝じゃらんレンタカー（拠点は `rentacarByArea`）

### Step 5. 物販の選び方

- 商品は「その釣り場のルール・魚種に合うもの」だけ。**合う商品がなければ置かない**（海上釣り堀用のマダイセットを護岸の記事に流用しない）
- 魚種別の商品は、海上釣り堀の対象魚（`.workspace/affiliate-tags/物販/fish-parameters.md` のコード）に限る。海釣り公園でしか狙わない魚（例: タチウオ）は `target_fish` と本文で触れるだけにし、専用品のカードは作らない。共通品（グリップ・ライフジャケット等）の reason で触れるのは可
- 足りない商品は記事に入れず、`.workspace/affiliate-tags/物販/` の台帳に「要登録」として書く
- 選定基準は `.workspace/affiliate-tags/物販/選定方針.md`（汎用性・竿の長さ・リール番手）

## 禁止事項

- 根拠のない「おすすめ宿」「最安」など、確認していない宿や価格の断定
- reason なしで汎用説明文だけのカードを本文中に置くこと
- 同じ面に同じ種類の CTA（宿泊2枚など）を並べること
- 検証していないディープリンク（エリアコードの推測）。`travel-area-links.json` にある URL だけを使う
- 都市近郊（E）の記事末に旅行 CTA を置くこと
- 公共交通のほうが安くて便利な施設でレンタカーを勧めること。その場合は「手ぶら＋電車・バス」を勧め、売らないことで信頼を取る
- 休園・アーカイブ施設（姫路など）でのマネタイズ

## 書いたあとのチェック

- [ ] 読者タイプと、その根拠（GA4・GSC・frontmatter）を作業メモに残した
- [ ] すべての CTA の直前、または `lead`／`reason` に「事実 → 理由」がある
- [ ] 1面1提案になっている。E では記事末に旅行 CTA がない
- [ ] すべての CTA に placement がある（`TackleCard` も）
- [ ] 数値はすべて frontmatter・本文・forAI・`.data-set` にある
- [ ] `pnpm run build` が通り、ページ上に赤い「IDが見つかりません」が出ていない

## 効果測定

- GA4: `gothere_click`（facility_id・link_type・placement）と `affiliatecard_click`（affiliate_id・placement）を placement 別に見る。エクスポートに列がない間は判定できない（設計メモ §4-A）
- 判定は4週合算。クリック率（クリック ÷ セッション）を改修前と比べ、VC・楽天・A8 の成約を確認する
- 結果は「適用ログ」に追記し、判定表や型を更新する
