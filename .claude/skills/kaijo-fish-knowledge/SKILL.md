# kaijo-angler 魚種ナレッジ優先の執筆ルール

魚種の事実・釣り方・地域差は `.data-set/fish-knowledge/` が正本。記事はここから作り、外部知識で埋めない。
規約（出所タグ・優先順位・進捗表）は `.data-set/fish-knowledge/README.md`。

## 執筆前の手順（毎回この順）

1. 対象の魚種 slug を決める（`src/content/blog/tactics/fish-strategy/` のディレクトリ名と同じ。例: `madai`）。複数魚種に触れる記事は、主役の魚種＋言及する魚種すべてを読む。
2. `.data-set/fish-knowledge/{slug}.md` を読む。**ファイルが無い魚種は、記事を書き始めずに次のどちらかを選ぶ**:
   - `_template.md` から作成し、既存記事と【DS】から下書きする（出所タグを付ける）
   - 運営者に「この魚種のナレッジが未作成。先に作るか、そのまま書くか」を確認する
3. 「2. 私の知見（【一次】）」が空欄なら、記事の独自性が弱くなることを運営者に伝え、記入を促す。**勝手に埋めない。**
4. 地域・施設に触れる場合は `src/content/blog/fishing-facility/` の `target_fish` と、`.data-set/【DS】海上釣り堀_地域別釣法・ブランド魚データベース.md` を確認する。
5. ナレッジに無い論点が必要になったら、WebSearch/WebFetch で調べ、結果を**先に**ナレッジファイルへ追記してから記事に使う（出典URL・取得日・【要検証】付き）。

## 書き方のルール

- **優先順位**: 【一次】> 【DS】> 【記事】> 外部検索。矛盾したら上位を採用し、下位は「要検証リスト」へ移す。
- **【要検証】は断定調で書かない。** 使うなら「〜とされる」「目安」と弱め、可能なら使わない。
- **体験談の捏造禁止**: 「〜したことがあります」「〜していた時期がありました」のような一人称エピソードは、【一次】に記録された内容だけを使う。無いときは書かない（一般論の導入に切り替える）。
- 数値（水温・号数・サイズ・時間）は出所タグがあるものだけ書く。出所のない数値を思いつきで足さない。
- 既存記事の記述を流用するときも【記事】扱い。裏取りが無ければ、リライトの機会に要検証リストへ回す。
- 強調は `<strong>`（`**` は使わない）、import は `~/`、アフィリエイトは `kaijo-ui-components` に従う。

## ナレッジの更新（記事を書いた後）

- 記事を書く過程で新しく判明した事実・運営者から聞いた話は、**記事より先に**ナレッジへ反映する。運営者の発言は【一次】、調べた情報は【要検証】から始める。
- 記事を公開・更新したら、ナレッジの「9. 既存記事のカバレッジ」と `last_reviewed` を更新する。
- 魚種ファイルを新規作成・状態変更したら `README.md` の進捗表も更新する。
- 既存記事の本文変更・コミットは運営者が明示するまで行わない（ナレッジ整備と記事修正は別作業）。
