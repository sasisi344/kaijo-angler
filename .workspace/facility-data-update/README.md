起票: 2026-10-02　／　親タスク: [[diagnosis-app-task]]（`.workspace/.task/`。「データ棚卸し結果」が根拠）

診断ハブ（`/find/`）・月別おすすめ・完全解析ページの土台として、**全施設の施設記事 frontmatter に不足パラメータを追加**する。施設は優先順位の高いものから**10件ずつのブロック**に分け、1ブロック1ファイルで個別に対応する。

## 優先順位の決め方

- GSC「ページ」W40（過去3か月）の**表示回数**。旧`/blog/{slug}`と新`/fishing-facility/{slug}`を**施設単位で合算**（旧URL側に残った表示も拾う）。同数ならクリック数→slug順
- 営業中の施設のみ順位付け（`status`が`closed`/`suspended`は別ファイル）
- **注意**: 順位は表示回数そのままで、診断の分析価値とは別。「海釣り公園型」（放流なし。例: 南港魚つり園護岸）も上位に入っている。月別放流分析の対象かどうかは、更新時に`facilityType`を確定してから判断する
- 再計算: 順位は2026-10-02時点のスナップショット。大きくアクセスが動いたら再生成する（生成元はW40の`ページ.csv`）

## 入力項目の定義（スキーマ案・未実装）

**スキーマの最終決定は、第1ブロック（10施設）の更新を実施した時点で行う**。以下は暫定案で、実際に埋めてみて項目の過不足・型・enum値を見直してから`config.ts`へ反映する。

`src/content/config.ts`の`fishingFacilityCollection`に**すべて`optional`で追加する予定**（既存記事を壊さない）。スキーマ追加前でも、frontmatterへ先に値を書いて構わない（現スキーマは未知キーを無視する前提。追加時に型検証でエラーが出たら直す）。根拠・現状の不足実数は[[diagnosis-app-task]]の表（#1〜#13）。

### A項目（全施設で必須）

| キー | 型・許容値 | 書き方 |
|---|---|---|
| `facilityType` | `sea-pond`（海上釣り堀）／`sea-park`（海釣り公園・桟橋）／`other` | 放流して釣らせる施設＝`sea-pond`。桟橋・護岸で天然魚を釣る＝`sea-park` |
| `stocked_fish` | 文字列配列 | 施設が**放流する**魚（マダイ・シマアジ等）。`sea-park`は空 |
| `wild_fish` | 文字列配列 | **天然**で狙える魚（アジ・キス・サバ等）。既存`target_fish`の振り分け元 |
| `price_min` / `price_max` | 数値（円・1人） | 最低／最高。無料は0。**入場料と釣り堀料金を混ぜない** |
| `price_type` | `entry-only`／`pond-1day`／`course` | 入場料のみ／釣り堀の1日料金／体験コース等 |
| `includes_gear` | boolean | 竿・エサ込みの料金か |
| `beginner_friendly` / `family_friendly` / `hands_free` | boolean | 初心者可／子連れ可／手ぶら可（レンタル完備）。タグの表記揺れを置き換える |
| `needs_ferry` | boolean（＋`ferry_info`文字列） | 渡船が必須か。必須なら所要分・乗船場所を`ferry_info`へ |
| `access_minutes` | 数値 | 最寄り駅またはICからの所要分（車／電車で`access_mode`を併記） |
| `reservation_type` | `required`／`recommended`／`not_required`／`first_come` | 既存`reservation`の自由文はそのまま残し、enumを追加 |
| `reservation_url` | URL | 予約ページ（なければ電話番号） |
| `official_site` | URL | 公式サイト（既存`website_url`が空の施設は新規収集） |
| `sns` | `{x, instagram, facebook}` | 放流情報などを発信している公式アカウント。放流収集の起点 |
| `verified_at` | `YYYY-MM-DD` | A項目の値を公式で確認した日 |

### B項目（上位ブロックのみ。第1ブロックで実施、第2〜3ブロックは余力で）

`open_months`（営業期間）／`closed_days`（定休日）／`peak_months`（混雑・繁忙期）／`takeout_rule`（持ち帰りルール）／`rod_length_limit`（竿の長さ制限・[[weekly-task]]Tier1と同時収集）／放流履歴の遡及収集（別ファイル。施設ID×日付×魚種×量×出典URL）

## 作業手順（1施設あたり）

1. 施設記事とGoogleマップ情報を開き、**公式サイト・公式SNSを一次情報として確認**（口コミ・まとめサイトは補助）。確認日を`verified_at`へ
2. A項目を埋める。既存の自由文（`average_price`・`reservation`・`target_fish`）は**消さず**、構造化キーを**追加**する
3. 本文と矛盾が出たら、frontmatterの数値と本文の表記を揃える（料金・予約・設備）
4. 完了したらブロックの見出しを`[x]`に。公式で確認できない項目は空のままにして、確認メモ欄に「公式で不明」と書く（推測で埋めない）
5. ブロック内10件が終わったら、スクリプトで**frontmatter検証**（型・enum・抜け）→ビルド確認。次ブロックへ
