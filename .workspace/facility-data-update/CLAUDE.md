# facility-data-update — 施設情報の更新・リライト 統合ルール

このフォルダの作業（施設記事の情報更新とリライト）は、**このファイルの手順に従う**。ほかのファイルとの役割分担は下表のとおり。手順が食い違ったらこのファイルを優先し、項目の定義（A/B項目・enum値）は `README.md` を優先する。

| ファイル | 役割 |
|---|---|
| `CLAUDE.md`（本書） | 作業の流れ・チェックリストの更新方法・forAI ブロックの扱い |
| `README.md` | 目的、優先順位の決め方、A/B項目の定義（キー・型・enum） |
| `block-XX_rank-*.md` | 施設ごとのチェックリスト、Web調査結果、個別記事対応タスク、**forAI メモの保管場所** |
| `manual-check.md` | ブラウザ・電話でしか確認できない項目のリスト |
| `needs-confirmation.md` | 要確認施設の一覧（全体の進捗） |
| `price-updates.md` | 料金を公式で確認して更新した記録 |
| `closed-suspended.md` | 閉店・休業施設の状態確認（リライト対象外） |

---

## 1. 全体の流れ

**最重要ルール: 見出しが `[-]` の施設 ＝ 運営者が確認・記入済みのリライト対象。リライトが終わったら `[x]` にして完了にする。**

```
運営者: 公式・現地・電話で確認 → 記事 mdx の末尾に > [!forAI] を書く → ブロックの見出しを [-] にする
Claude: [-] の施設を見つける → forAI を最優先に記事をリライト → forAI を記事から外してブロックへ保管
        → 検証 → 見出しを [x] にして進捗を更新
```

- **Claude が `[-]` を付けることはない**。`[-]` は「運営者が確認して forAI を書いた」という印で、運営者だけが付ける
- `[ ]`（未確認）の施設は、運営者に頼まれない限りリライトしない

## 2. チェックリストの記号

ブロックファイルの施設見出し `### [?] N. 施設名 — \`slug\`` の状態:

| 記号 | 意味 | 付ける人 |
|---|---|---|
| `[ ]` | 未着手 | — |
| `[-]` | 運営者が確認済みで、記事末に forAI あり（リライト待ち） | 運営者 |
| `[x]` | forAI を反映してリライト完了 | Claude |

このルールを作る前から `[x]` が付いている施設（block-01 のあっとしぃーなど）も、リライト済みとして扱う。付け直さない。

### `[x]` にするときに一緒に更新するもの

1. **施設見出し**: `[-]` → `[x]`
2. **ブロック冒頭の完了数**: `完了: n/10` を数え直す
3. **A/B項目の小チェック**（`更新（A=…）` `更新（B=…）` 行）: 今回 frontmatter に**実際に書いた項目だけ** `[x]`。公式で不明なものは `[ ]` のまま
4. **「個別記事対応タスク」の該当行**: `[x]` にし、`（YYYY-MM-DD リライト）` と変更点の要約を書く。その下に forAI の原文を保管する（§4）。該当行がなければ追加する
5. **`needs-confirmation.md`** の該当施設を `[x]`
6. **`README.md` の進捗表**: ブロックの状況が変わったら一言更新
7. 料金を変えたら `price-updates.md` に旧→新を1行追加

## 3. forAI ブロックの書き方（運営者向け）

記事 mdx の**いちばん最後**（まとめ・筆者の一言のあと）に書く。書式は自由でよい。箇条書きにすると、ラベルを付けたとおりに読み取りやすい。

```mdx
> [!forAI]
> - 【事実】営業時間 4〜11月 5:00〜19:00／12〜3月 7:00〜17:00（公式で確認）
> - 【事実】レンタル竿 1本1,000円
> - 【感想】駐車場代が高い。開園前に並べる近くの人が有利
> - 【指示】タイトルを「◯◯」寄りに。旧来の「科学的根拠」の段落は削除
> - 【要確認】レンタルの料金は電話で聞く予定
```

| ラベル | Claude の扱い |
|---|---|
| 【事実】 | 本文・frontmatter に反映する。出所（公式・現地・電話）があれば一緒に書く |
| 【感想】 | 「筆者の一言」や注意点として、意見だとわかる書き方で使う。広げて体験談をつくらない |
| 【指示】 | そのとおりに直す（タイトル・構成・削除など） |
| 【要確認】 | 本文には書かない。ブロックのメモに残す |

- 後から足すときは `> 追記（2026-10-16）: …` のように日付を付ける
- **はじめて項目**（2026-10-27〜。上位20施設から）: 次の5点を【事実】で書く。Claude は frontmatter の `facility_details.first_timer` に入れ、料金の節の直後に「はじめての方へ」節（`<FirstTimerGuide />`）を置く。分からない項目は「不明」と書く（記事では「予約時に聞くこと」に回る）。詳細は `.workspace/.task/first-timer-design.md`

```mdx
> [!forAI] はじめて項目（確認日 2026-11-08 / 出所 公式URL または 電話）
> - 【事実】レンタル：竿・リール・仕掛け 1,000円、エサは受付で販売
> - 【事実】貸出：ライフジャケット無料、タモは各イカダに常備
> - 【事実】スタッフ：使い方を教える・タモ入れ・針外し
> - 【事実】釣果保証：なし（お土産魚もなし）
> - 【事実】締め・捌き：有料（1匹200円）
> - 【感想】はじめての人がつまずきやすい点（あれば）
```
- ラベルなしの自由文でもよい。どの扱いか迷う文は Claude から運営者に確認する

> ⚠ このプロジェクトには `[!xxx]` 形式（GitHub のアラート記法）を処理するプラグインがない。forAI が残ったままデプロイすると、**ふつうの引用として公開ページに表示される**。リライトのときに必ず記事から外す。forAI が残っている記事はデプロイしない。

## 4. リライトの手順（Claude）

### 対象を探す

```bash
grep -n "^### \[-\]" .workspace/facility-data-update/block-*.md   # リライト待ちの施設
grep -rln "\[!forAI\]" src/content/blog/                          # forAI が残っている記事
```

両方の結果が合わない（`[-]` なのに forAI がない、forAI があるのに `[ ]`）ときは、作業前に運営者に確認する。

### 読む順

1. 記事末の **forAI**（最優先）
2. ブロックファイルの「調査結果」表と「個別記事対応タスク」の該当行
3. `manual-check.md`・`price-updates.md` に該当施設の行があれば読む
4. 使うスキル: frontmatter は `kaijo-content-schema`、魚種に触れる段落は `kaijo-fish-knowledge`、アフィリエイト・CTA は `kaijo-affiliate-sales` → `kaijo-ui-components`

### 書くときのルール

- **forAI と調査結果（公式確認済み）が食い違ったら forAI を優先**し、食い違いがあったことをブロックのメモに書く
- forAI・公式・`.data-set` にない料金・時間・所要時間・体験談は書かない（推測で埋めない）
- 運営者に確認して訂正したことは、ブロックのメモに「（運営者確認）」と書いて残す（例: 糸満のバス会社・所要時間の訂正）
- frontmatter: A/B項目を `README.md` の定義どおりに追加。既存の自由文（`average_price`・`reservation`・`target_fish`）は消さない。`verified_at` と `lastmod` を今日の日付に
- 本文の強調は `<strong>`（`**` は使わない）。import は `~/`
- slug は変えない（正式名称が変わってもタイトル・本文だけ直す）
- アフィリエイトの設計を決めたら、`kaijo-affiliate-sales` の「適用ログ」に1行追加

### forAI を外して保管する

1. 記事 mdx から `> [!forAI]` ブロックを削除する
2. ブロックファイルの「個別記事対応タスク」の該当行の下に、**原文のまま**保管する

```markdown
- [x] **南港**（2026-10-16 リライト）: 変更点の要約……
  - forAI メモ（2026-10 運営者記入・原文）: ……
  - forAI 追記（2026-10-16・原文要約）: …… → 本文「アクセス」に反映済み。◯◯は運営者確認で△△に訂正
```

原文は改変しない。訂正・反映先は `→` のあとに書き足す。

### 検証

```bash
node scripts/check-facility-frontmatter.mjs
grep -rn "\[!forAI\]" src/content/blog/   # リライトした記事に残っていないこと
pnpm run build                            # デプロイ前
```

## 5. 完了の条件

次がすべてそろったら `[x]` にする。

- [ ] forAI の【事実】【指示】がすべて本文・frontmatter に反映されている（【要確認】はメモに残っている）
- [ ] 記事に forAI ブロックが残っていない
- [ ] forAI の原文がブロックファイルに保管されている
- [ ] `verified_at`・`lastmod` を更新した
- [ ] `check-facility-frontmatter.mjs` が通る
- [ ] §2 の「一緒に更新するもの」を更新した

反映しきれない項目（公式で不明・運営者の回答待ち）が残っても、forAI の内容を反映し終えていれば `[x]` にしてよい。残りは該当行の下に `- 残: …` と書き、必要なら `manual-check.md` に移す。
