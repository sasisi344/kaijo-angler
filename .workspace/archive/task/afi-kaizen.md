# 海上釣り堀施設で旅行商品アフィリエイト収益を最大化する方法(アナリストレポート)

## 1. 問題の構造化:なぜ「立地の相性」と「実績」が乖離しているか

海上釣り堀は本来、以下の条件がすべて揃っている稀有な業態です。

- 交通不便な立地 → 交通手段(飛行機・新幹線・レンタカー)の需要が発生しやすい
- 海沿い・地方部 → 前泊需要が発生しやすい
- レジャー目的 → 周辺観光との併売余地がある

にもかかわらず売れていないのは、**「需要がない」のではなく「需要が可視化される前にユーザーが離脱している」**という導線設計上の欠陥が原因である、というのが本レポートの中心仮説です。

これを検索意図で分解すると:

|セグメント|検索意図|現状の対応|状態|
|---|---|---|---|
|仮説A:近隣・日帰り層|施設情報のみで完結|施設ページが対応済み|適切|
|仮説B:旅行検討層|「行く価値があるか」「どう行けば良いか」で迷っている|**専用コンテンツが存在しない**|**機会損失**|

→ 施設ページのCVR(コンバージョン率)を落とさずに、**仮説Bのためだけの新規面(ページ)を立てる**ことが最優先の構造改革になります。

## 2. 収益構造の分解:120%達成のためのKPIツリー

アフィリエイト収益は以下の掛け算で決まります。

```
アフィリエイト収益 = 検索流入数 × 旅行検討層の比率 × コンテンツ到達率 × クリック率 × 商品単価
```

現状、仮説Bの層に対しては「専用コンテンツが存在しない」ため、上式の**「コンテンツ到達率」がほぼゼロ**になっています。これがボトルネックの正体です。

したがって、120%増を狙う場合、以下の3つのレバーに分解して積み上げるのが現実的です。

|レバー|施策|期待効果の根拠|
|---|---|---|
|① 流入数の拡大|都道府県名・ハブ都市名でのロングテールKW獲得|現状ゼロだったクエリ群を新規獲得できるため、絶対数として純増|
|② 単価の引き上げ|「ゆったり」軸(宿泊+周辺観光+レンタカー)への誘導強化|交通単体より宿泊付きセット商材の方が単価・成約率が高い|
|③ 離脱の抑制|「行く価値があるか」への不安解消コンテンツを前半に配置|比較検討層の離脱ポイントを塞ぐことでCTR改善|

**120%という数字の妥当性**:現状「仮説B向けコンテンツ流入がゼロ」という前提に立てば、新規面を1つ追加するだけでその面からの収益は0→1になります。既存の施設ページ経由の収益を100とした場合、新設ページで20〜(理想的には)それ以上を積み増すことは、競合が同様の設計をしていない限り、KWの空白地帯を埋めるだけで十分到達可能な水準です。

## 3. 実行フレームワーク:ハブ都市モデル

### 3.1 面設計

```
目的地(釣り堀のある都道府県)を主語にした「地方タブ構造」
├─ 関東地方から(ハブ:東京)
├─ 関西地方から(ハブ:大阪)
├─ 中部地方から(ハブ:名古屋)
├─ 九州地方から(ハブ:福岡)
```

- 地方名は情報のコンテナに過ぎず、**実クエリを拾うのはハブ都市名・周辺都道府県名の見出し**
- ハブ都市は厚く(交通比較・所要時間・費用試算をフル掲載)、周辺県は差分ベースで軽量化 → 重複コンテンツ化を回避しつつ執筆コストも抑制

### 3.2 距離帯別の提案軸の作り分け

| 距離帯        | 交通の前提         | 主要商材                 |
| ---------- | ------------- | -------------------- |
| 近距離(車で数時間) | 自動車移動が前提      | 高速道路情報・SA/PA観光・レンタカー |
| 遠距離(飛行機圏)  | 空路+レンタカー/公共交通 | 航空券・現地レンタカー・前泊宿泊     |

同じ「ゆったり・コスパ・最短」という3軸フレームでも、中身の交通手段は距離帯ごとに再設計する必要がある。

### 3.3 内部リンク設計

- 施設ページ:現状維持。「遠方からお越しの方はこちら」の一文リンクのみ追加(仮説Aユーザーの体験を阻害しない)
- 新設ページ → 施設ページ:旅程の文脈で自然に戻す(回遊率・SEO内部評価の両方に寄与)

## 4. 優先順位付け(リソース最適化)

全地方×全都道府県のフル展開は工数対効果が悪いため、以下の順で着手する。

1. **データ検証フェーズ**:サーチコンソールで「都道府県名+施設名/行き方」の既存クエリ有無を確認、GA4で流入地域の実数を把握
2. **テストケース選定**:アクセスが複雑(＝コンテンツの介在価値が高い)エリアを1つ選び先行展開(例:四国・北陸)
3. **ハブ都市から着手**:東京・大阪・名古屋・福岡など、検索ボリュームが見込める都市を優先
4. **横展開**:効果検証後、他エリア・他施設へテンプレート化して展開

## 5. リスクと留意点

- 都道府県ごとに均等な文量を書くと重複コンテンツ判定のリスクがあるため、**ハブ都市を厚く、周辺県は差分**という設計を必ず徹底する
- 施設ページに旅行広告を後付けで混在させると、既存の仮説Aユーザーの体験・CVRを下げるリスクがあるため、**面を分離したまま接続する**という原則を崩さない
- 「ゆったり」軸(宿泊+周辺観光)が単価的に最も収益インパクトが大きいため、コンテンツの厚みもここに最優先で配分する
