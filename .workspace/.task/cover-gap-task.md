## 4. カバーの作り方

- 置き場所は記事と同じフォルダの `cover.jpg`、frontmatter は `image: ./cover.jpg`（クォートなし）
- アクセス記事6本（C3）は、費用を抑えるため共通の1枚にする（2026-07-08 のユーザー方針「同じカテゴリ・地域の記事はカバーを使い回す」）。`src/content/blog/column/travel/access/_covers/access-cover.jpg` に置き、6本とも `image: ../_covers/access-cover.jpg`（6本とも `access/` の直下にあるので同じ書き方でよい）。場面は「海沿いの道を釣り場へ向かう車と、遠くに生け簀のある湾」
- タックル記事のカバーには、特定のメーカーやロゴが読める描写を入れない
- 差し替えた 640×640 の `cover.png` は消す（`image:` から参照されていないことを確かめてから）

## 5. 横断の注意

- **一人称の言い回し**: `harris-importance` 32行・`cooler-box-guide` 34行・`fish-shipping-guide` 34行に「私なら〜」がある。筆者の体験の記録がない内容なので、リライトでは「おすすめは〜」「〜の順に決めると〜」の形に直す（体験を作らない）
- **内容の重なり**: `column/travel/cooler-box-guide`（遠征での運び方・宅配便の規定）と `tactics/gear/cooler-box-selection`（容量・保冷力の選び方）は、役割を書き分けて相互にリンクする。`ensei-guide` と `setouchi-access-guide` は瀬戸内の行き方が重なる。統合や301はこのタスクではしない（運営者の判断）。重なりは報告書に書く
- **数値の出所**: タックルの号数・サイズは `.data-set/fish-knowledge/` に出所のあるものだけ書く。料金・所要時間・規定は公式で確かめ、確認日を添える
- **リライトの基準**: 読者が最初の画面で「自分はどれを選べばいいか」が分かる形にする。結論→理由→選び方の順。見出しは事実の言い方にし、煽り語を使わない（`kaijo-writing-rule.md`）

## 6. 各記事の進め方（共通）

1. 記事を最後まで読み、§3 の判定を確かめる（判定と違えば報告書に書く）
2. リライトする（C1・C2 は全面または部分、C3 は軽め）
3. インフォグラフィックのプロンプトを書いて生成し、該当の節に入れる（余地が「低い」記事は作らない）
4. カバーのプロンプトを書いて生成し、`image:` を入れる
5. `lastmod` を作業日にし、`pnpm build` を通す
