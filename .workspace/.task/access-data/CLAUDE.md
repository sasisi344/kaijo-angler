# access-data — アクセスデータ格納ルール

GA4・GSC の週次エクスポートを置く場所。**分析の前に必ず [`INDEX.md`](INDEX.md) を読む**（週ごとの期間・ファイル名・比較可否が一覧化されている）。ファイルを開いて期間を推測しない。

PPDCA（分析→`next-task`/`weekly-task` 起票）の手順は skill `kaijo-weekly-ppdca`（`.claude/skills/kaijo-weekly-ppdca/SKILL.md`）。

## ディレクトリ構成

```
access-data/
├── CLAUDE.md / INDEX.md                  # 本ルールと週次インデックス
├── 2026-0621-3month-page.csv             # 3か月スナップショット（2026-06-21時点・旧 /blog/ URL 時代のベースライン）
├── 2026-0621-3monthquery.csv             #   ↑ scripts/analyze-query-mix.mjs・analyze-region-density.mjs の既定入力
└── weekly-report/<年>/<wNN>/             # 週次データ。1週 = 1フォルダ
```

## 週番号（wNN）の決め方

- **wNN = データ取得を行う日曜が属する週**。週は日曜始まりで、1/1 を含む週が第1週（GA4 の週番号と同じ）
- 2026年は 1/1 が木曜なので、第N週の日曜 = 12/28 + 7×(N−1)。w41=10/4, w42=10/11, w43=10/18, w44=10/25, w45=11/1
- 対象データは**その日曜の前の日曜〜土曜（7日間）**。例: w42（10/11取得）= 10/4〜10/10
- 既存の例外（w37 の番号ずれ、欠番）は INDEX.md の備考で管理し、**既存フォルダはリネームしない**（`scripts/`・各タスクファイルからの参照が壊れる）

## 新規フォルダ・ファイル命名（w42 以降）

フォルダは小文字 `wNN`。ファイル名は ASCII で固定する。

| 種別 | ファイル名 | 取得元 |
|---|---|---|
| GA4 | `wNN-ga4.csv` | GA4 探索「週報PPDCA用-1week-自由形式」。ヘッダー4行目の期間コメント（`# YYYYMMDD-YYYYMMDD`）は消さない |
| GSC クエリ | `wNN-gsc-query.csv` | GSC 検索パフォーマンス →「クエリ」タブ |
| GSC ページ | `wNN-gsc-page.csv` | 同「ページ」タブ |

- 旧名の `クエリ.csv` / `ページ.csv`（GSC 既定名）・`kaijo-*`・`w29-*` は w41 以前に限り許容。**取得したら INDEX.md に1行追加するまでが取得作業**
- GSC の CSV には期間が書かれない。取得時に GSC 画面の期間表示を確認し、**INDEX.md の「GSC期間」に実日付を必ず記入**する

## 期間ルール（齟齬防止）

**w41 以降は全ブログ共通で「GA4・GSC とも直近7日間」。**

| 時期 | GA4 | GSC |
|---|---|---|
| w24〜w28 | 7日（ヘッダーは終了日含む8日表記） | 7日（GA4 の Search Console 連携レポート。ランディングページ×クエリ） |
| w29 | 7日 | 7日 vs 直前28日（比較列あり） |
| w37 | 28日 | **3か月（推定）** |
| w40 | 8日 | **3か月 vs その前3か月**（指標ごとに列が2本。1本目が当期） |
| **w41〜** | **7日（w41 は終了日含む8日）** | **7日（単一列）** |

比較・集計時のルール:

1. **GSC の絶対値（クリック・表示回数）は期間の異なるファイル同士で比べない。** w40 と w41 の前週比は出さない。w41 の GSC に対する WoW は **w42 から**
2. w40 以前の3か月データは「長期ベースライン」として使う。週平均に換算する場合は ÷13（3か月≒13週、概算）。CTR・掲載順位は率なので換算不要だが、7日データはサンプルが小さいので下の閾値を守る
3. **単週の7日 GSC データは「異常検知（急落・急騰）」まで。** 施策の効果判定・順位判断は**直近4週分を合算**してから行う（クエリ単位は7日だと表示回数50以上が3件しかない）
4. GA4 の期間日数はヘッダーの日付で数える（終了日を含む）。日数が違うファイル同士は**日平均（セッション÷日数）で比較**。w40・w41 は終了日が重複（9/26）しているので、w41→w42 の GA4 比較も日平均で行う
5. 速報の判定閾値（初期値）: ページ=表示回数 50 以上、クエリ=表示回数 20 以上。これ未満の CTR・順位は判断材料にしない

## データ読解の注意

- **URL**: GSC・GA4 とも旧 `/blog/<slug>/` と新 `/fishing-facility/<slug>/` 等が混在する。分析は **slug 単位で新旧を合算**する。ただし **`/blog/intelligence/` は現行 URL**（旧 URL ではない）ので合算・除外の対象にしない
- **GA4 の行は全ディメンションの組み合わせ**（w40〜: ページ×参照元×イベント名、w41〜: +市区町村）。1行目の「総計」行が全体値。**セッション数を集計するときはイベント名で足し合わせない**（`session_start` 行の合計がセッション総数と一致する。他イベント行を足すと二重計上）
- GA4 のイベント名: `affiliatecard_click`（物販）・`gothere_click`（観光導線）。カスタムディメンション `affiliate_id`（2026-09-30登録）・`placement`/`facility_id`（2026-09-20登録）は**登録日以降のデータのみ**有効
- GSC クエリ CSV は匿名クエリが含まれず、ページ CSV より合計が小さい。サイト全体の合計は**ページ CSV の合計**を使う
- 列構成の違い（GA4）: w24〜w28=4セグメント並列／w29・w37=ページ×LP×参照元／w40=+イベント名・イベント数／w41=+市区町村
