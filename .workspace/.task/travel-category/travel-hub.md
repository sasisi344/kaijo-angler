### なぜ切り替えるか

コンテンツ型アプローチの限界：

- 「アクセス情報を記事で網羅する」→ 読んで判断してもらう間接導線
- 記事を増やすほど更新コストが積み上がる
- 北陸・四国・九州は施設数が少なく投資対効果が薄い

機能型アプローチの優位性：

- 施設ページにいるユーザーは **すでに「行く気がある」状態**
- 位置情報 × ワンタップで「行く手段」を提示 → 自然なアフィリエイト着地
- コンポーネント 1 本を全施設記事に展開 = 170 記事に一括適用

## 1. GoThere コンポーネント — 概要設計

### ユーザー体験フロー

```
施設記事を読んでいる
　↓
「この施設へのアクセスを調べる」ボタン（常時表示）
　↓
出発地を入力 or 位置情報を取得（任意）
　↓
┌──────────────────────────────────┐
│  電車・バス  →  Yahoo! 路線（アフィリ）  │
│  新幹線      →  えきねっと / EX アプリ   │
│  飛行機      →  スカイスキャナー（アフィリ）│
│  宿泊        →  じゃらん / 楽天トラベル  │
│  レンタカー  →  じゃらんレンタカー       │
└──────────────────────────────────┘
　↓
そのままアフィリリンクで予約へ
```

### 表示ルール

| 条件 | 表示するアフィリ枠 |
|---|---|
| 施設が離島 or 半島（フェリー必要） | フェリー予約を最上位に |
| 施設が新幹線駅から 60 分以上 | レンタカーを推奨欄に |
| 施設に「宿泊プランあり」フラグ | 宿泊枠を表示 |
| デフォルト | 電車・車・宿泊の 3 枠 |

## 2. 実装設計

### 2.1 コンポーネント構成

```
src/
├── components/
│   └── widgets/
│       └── GoThere/
│           ├── GoThere.astro          # メインコンポーネント
│           ├── GoThereButton.astro    # トリガーボタン
│           └── AffiliateLinks.astro   # アフィリリンク出力
└── data/
    └── facility-access.ts             # 施設ごとのメタデータ
```

### 2.2 施設メタデータ（facility-access.ts）

施設ごとに以下を定義する。frontmatter に持たせるか外部ファイルに集約するかは実装時に判断。

```ts
type FacilityAccess = {
  facilityId: string       // fishing-facility の slug と一致
  prefecture: string       // 都道府県
  nearestStation?: string  // 最寄り駅
  nearestIC?: string       // 最寄り IC
  ferryRequired: boolean   // フェリー必須かどうか
  stayPlanAvailable: boolean // 宿泊プランの有無
  rentalCarRecommended: boolean
  affiliateRegion: string  // じゃらん・楽天のエリアコード
}
```

### 2.3 GoThere.astro — インターフェース

```astro
---
// Props
interface Props {
  facilityId: string
  facilityName: string
}
---

<!-- 出発地入力 or 位置情報取得 -->
<!-- アフィリリンク生成・出力 -->
```

### 2.4 アフィリリンク生成ロジック

各アフィリエイトのディープリンクに施設の地域コードを埋め込む。

| サービス | リンク形式 |
|---|---|
| じゃらん | `https://www.jalan.net/...?area={affiliateRegion}` |
| 楽天トラベル | `https://travel.rakuten.co.jp/...?f_area={affiliateRegion}` |
| じゃらんレンタカー | `https://www.jalan.net/rentacar/...?area={affiliateRegion}` |
| スカイスキャナー | `https://www.skyscanner.jp/...` （出発地空港を近隣から推定） |

## 3. 施設記事への組み込み方針

### 配置場所

施設記事（`fishing-facility/**/index.mdx`）の **「アクセス」セクション末尾** に GoThere を設置。
既存のラストマイル情報（IC・最寄り駅・駐車場）はそのまま残す。GoThere はその補完として置く。

```mdx
## アクセス

最寄り IC：○○ IC から車で約 20 分。駐車場 50 台。

<GoThere facilityId="fishing-park-triton" facilityName="フィッシングパークトリトン" />
```

### 展開順序

全 170 施設に一括展開するが、アフィリメタデータの整備を段階的に行う。

| フェーズ | 対象 | 内容 |
|---|---|---|
| Phase 1 | アクセスハブ整備済み施設（近畿・関東・東海） | メタデータ + GoThere 設置 |
| Phase 2 | 残り施設 | 順次展開 |

## 4. 入口コンテンツの考え方

GoThere を活かすための入口は **既存記事の改善**で足りる。新規記事の大量追加は不要。

| 入口タイプ | 現状 | アクション |
|---|---|---|
| 施設記事（170 本） | GoThere なし | Phase 1 から順次設置 |
| ポイント記事（攻略・魚種別） | 施設リンクあり | GoThere を持つ施設へのリンクを確認 |
| 県別まとめ（fishing-facility インデックス） | 一覧のみ | GoThere 設置済み施設を「アクセス情報あり」でフィルタ表示（将来対応） |

「釣り堀のある都道府県に限定する必要はない」という前提のもと、
旅行アフィリの地域コードは施設の所在地に紐付ければよく、
記事の地理的カバレッジを広げる必要はない。
